# Captured human question dispositions — partial AM-05.06

The question-dispositions export provides createQuestionDispositionState, recordQuestionDispositions and inspectQuestionDispositions. This is pure private bookkeeping over an explicitly host-authorized human context and complete captured planning/effort JSON. It has no owning database, HTTP endpoint, authentication, assignment delivery, execution or closure authority. Existing owning coverage endpoints and Visual coverage profiles remain unchanged and still report every question unresolved.

Each immutable review covers EVERY question in the selected latest captured plan, in original order, with an explicit unresolved, deferred or assigned disposition and rationale. Assigned questions name a host human identifier; the identifier does not prove membership, identity, delegation or delivery. Deferred and assigned questions require a canonical UTC millisecond review timestamp after the recorded review time. Unresolved questions cannot name an assignee or review time. One to sixteen distinct literal reopening triggers are required; triggers never execute or reopen anything.

Each review records the exact plan, whole planning count, global effort sequence and SHA256 of canonical captured planning/effort histories. Inspection reconstructs and validates every original history prefix, exact plan/question joins and original digest. Append uses global expected sequence and the exact last review for that logical plan; no forks, overwrite, deletion, eviction or silent rebase. Historical decisions, corrections, actor/time/request metadata and original bases remain available. Metadata/digests do not authenticate a writer or establish research, source permission, truth or tamper resistance against a party replacing both history and digest.

A changed plan edition or ANY captured planning/effort append conservatively makes a prior review require fresh review. Reaching any assigned/deferred review time also requires fresh review. The table then exposes unresolved defaults while retaining the actual prior review and whole review history; it never transfers an old assignment/deferral to a changed basis. Host current clock, authentication, resource/SourceConsent rights, durable history/own-DB adapter, concurrency, protected read/write interface and visual/browser/AT/live qualification remain pending. Review time is host metadata, not SQL commit time. Absence of changed metadata is not proof of work completeness.

Host input/CPU/heap limits are mandatory; cloning, prefix reconstruction and validation are synchronous, not a sandbox. This module cannot establish snapshot authenticity or monotonicity across separate host invocations. No schema migration, SQL/API/SDK pin/contracts/original15-engine/122-task IDs or dependency change.
